# IPVanish

## TLDR

```sh
docker run -it --rm --cap-add=NET_ADMIN --device /dev/net/tun \
-e VPN_SERVICE_PROVIDER=ipvanish \
-e OPENVPN_USER=abc -e OPENVPN_PASSWORD=abc \
-e SERVER_COUNTRIES=Netherlands qmcgaw/gluetun
```

```yml
version: "3"
services:
  gluetun:
    image: qmcgaw/gluetun
    cap_add:
      - NET_ADMIN
    devices:
      - /dev/net/tun:/dev/net/tun
    environment:
      - VPN_SERVICE_PROVIDER=ipvanish
      - OPENVPN_USER=abc
      - OPENVPN_PASSWORD=abc
      - SERVER_COUNTRIES=Netherlands
```

💁 To use with Wireguard, see the [Wireguard section](#wireguard) below.

## Required environment variables

- `VPN_SERVICE_PROVIDER=ipvanish`
- `OPENVPN_USER`
- `OPENVPN_PASSWORD`

## Optional environment variables

- `SERVER_COUNTRIES`: Comma separated list of countries
- `SERVER_CITIES`: Comma separated list of cities
- `SERVER_HOSTNAMES`: Comma separated list of server hostnames. Beware this is the narrowest filter, so if you set this to a single hostname and this hostname disappears from the Gluetun servers data due to an update, your container will no longer work until this filter is changed. I would suggest avoiding it unless you know this reliability risk.

## Wireguard

IPVanish Wireguard is not supported natively by Gluetun, since each Wireguard configuration generated by IPVanish only works with the one server it was generated for.
You can still use Wireguard with the [custom provider](custom.md#wireguard), using a configuration file generated by IPVanish.

1. Sign in to your IPVanish account portal.
1. In the left menu, go to **Service Management** and then **WireGuard** to open the [WireGuard Configuration Generator](https://www.ipvanish.com/blog/generate-wireguard-configurations/).
1. Select the server location you want, and click **Generate** to download the configuration file.
1. Rename the file to `wg0.conf` and bind mount it to `/gluetun/wireguard/wg0.conf`:

    ```sh
    docker run -it --rm --cap-add=NET_ADMIN --device /dev/net/tun \
    -e VPN_SERVICE_PROVIDER=custom -e VPN_TYPE=wireguard \
    -v /yourpath/wg0.conf:/gluetun/wireguard/wg0.conf:ro \
    qmcgaw/gluetun
    ```

    ```yml
    version: "3"
    services:
      gluetun:
        image: qmcgaw/gluetun
        cap_add:
          - NET_ADMIN
        devices:
          - /dev/net/tun:/dev/net/tun
        volumes:
          - ./wg0.conf:/gluetun/wireguard/wg0.conf:ro
        environment:
          - VPN_SERVICE_PROVIDER=custom
          - VPN_TYPE=wireguard
    ```

The file can be used as downloaded: Gluetun ignores its `DNS` line and uses its own [DNS settings](../options/dns.md) instead.

If you would rather not mount the file, you can set these environment variables from its values instead:

| Configuration file value | Environment variable |
| --- | --- |
| `[Interface]` `PrivateKey` | `WIREGUARD_PRIVATE_KEY` |
| `[Interface]` `Address` | `WIREGUARD_ADDRESSES` |
| `[Peer]` `PublicKey` | `WIREGUARD_PUBLIC_KEY` |
| `[Peer]` `Endpoint` IP address | `WIREGUARD_ENDPOINT_IP` |
| `[Peer]` `Endpoint` port, usually `51820` | `WIREGUARD_ENDPOINT_PORT` |

⚠️ Gluetun always connects to the single server in the configuration file, so the server filters such as `SERVER_COUNTRIES` do not apply.
To change server, generate a new configuration file for another location.
Using the private key and address of one configuration with the public key and endpoint of another does not work.

⚠️ The configuration file contains your private key: keep it secret and do not share it in issues or logs.
You can also pass it as a [Docker secret](../advanced/docker-secrets.md) instead of bind mounting it: Gluetun reads it from `/run/secrets/wg0.conf` by default, or from the path set with `WIREGUARD_CONF_SECRETFILE`.
